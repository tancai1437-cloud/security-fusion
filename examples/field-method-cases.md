# 方法融合的验收场景

这些是方法选择的审阅场景，不是实际目标测试结果，也不代表独立模型评测。用于检查后续修改是否破坏范围、证据语义和有效推进。对应 [现场方法](../references/field-methods.md)。

| 输入事实 | 应作出的决定 | 不能推出的结论 |
|---|---|---|
| 正常页面和不存在路径都返回相同的 200 登录 HTML；已知业务 API 返回明确身份错误 | web 记录统一兜底；api 记录认证前提，登录后检查受阻；下一步看已知身份入口或独立面 | API 匿名可读；整个站点已通过测试；继续重复尝试同一拒绝响应 |
| 同一主机首页已检查，新响应出现另一个业务接口；该接口在已绑定范围内 | 带来源记录新接口，在 inputs 区分路径、方法和身份，查重后安排相应专项 | 同主机全部 done；新 URL 立即继承旧结论 |
| JS 出现接口路径、参数构造和外域 URL | js 先核对实际调用；外域作为待核对线索，范围与绑定满足后才进入执行 | 字符串一定是活接口；外域一定属于本次可测范围 |
| 受控用户成功读取自己的文件，但没有跨归属对照 | 保留正常基线；只有具备获准的其他测试对象才做相应对照，缺前提记受阻 | 因返回 200 就确认文件越权 |
| 当前已有可复现的业务状态异常，另一个搜索词可以找到更多入口 | business 优先补齐当前异常的成立条件与影响证据；新词排队，受阻或完成后再选 | 扩大搜索数量就是有效进展；为了更高等级必须扩大写操作 |
| 同产品两个实例外观一致，仅验证了其中一个 | 记录采样边界；以实际构建、API 和身份行为判断差异，未测实例不自动 done | 标题相同就是同一套控制；一个实例阴性意味着其余安全 |
| 又一个目标出现已有方法能解释的问题，没有新增条件；另一个案例发现新的误判原因 | 前者留案件；后者带来源和反例形成经验修订候选，审核后替代旧版 | 每份报告新增经验；一次失败就删除通用方法；中低风险经验一律不要 |

共同完成要求：先取得证据再扩展计划，受阻项有恢复条件，阴性和未测边界可恢复，报告无完整密钥或会话值。第一份证据和每轮推进均沿用 start/run 或当前 MCP 的实际调用协议，不通过增加必读文件验收。
