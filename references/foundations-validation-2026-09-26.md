# 基础能力改造验证（2026-09-26）

验证对象是 [基础能力改造](foundations.md) 的实现。此前任务执行困难不是靠扩写 Skill 规则解决；本轮改动落在宿主校验、案件归属、持久证据和恢复投影。

## 自动化验证

本机 Python 全套 150 项：147 通过，3 项因 Windows 环境条件跳过。其中宿主桥接包装运行 18 个 Node 场景；可选 DSH SDK 包装另运行 1 个真实 SDK 场景。本机设置 FUSION_DSH_RUNTIME 指向已安装运行时；CI 未提供该 SDK 时明确跳过该项，不下载新依赖。

主要行为已覆盖：

- 同 cwd 两会话写同名文件互不覆盖；共享文件不变；案件外路径和目录链接逃逸在结构化写入前拒绝。
- 产物同名更新后仍可按原证据 ID 获取旧内容；清理原临时文件不影响正式副本；外案 ID、篡改证据不能读取。
- 不同 slot 无法占用同一 provider/context_id；历史重复占用也不能继续执行，释放后可恢复。
- 长方法受预算约束时，前置结果优先保留，方法来源/完成条件可见；完整方法明确标为按需读取。
- 验收条件不能靠未复核或外案回执满足；上游尝试换版后相关验收失效，独立分支不受影响。
- 同项目已审核方法自动召回，目标事实不共享；不同路径的同名项目文件夹不共享经验命名空间。
- 已保存工具回执但未写账的中断只补记，不重发；未知结果不会自动变成成功。已有 12 次模拟压缩/进程重建的查重复用测试继续通过。
- 真实 DSH Session 连续 12 次替换恢复状态后只保留一份完整当前块；原任务消息和所有日志保留，兼容旧版多个恢复块。
- 真实 DSH schema 验证 request 的对象/编码对象使用同一规则；缺工具必填参数不会创建案件或失败检查。

发布文件集的引用与路由校验通过。仓库的忽略目录含旧对比项目，故校验使用实际发布文件集，避免把不发布的参考仓库断链算入本包。结构 gate 无新增退化；未配置 sentrux 自定义架构规则，不能将 check 的“无规则”当作通过。

## 真实模型两轮恢复

Windows，DSH 0.1.2-rc.1；模型使用现有 bendi / Qwen3.8-27B-Uncensored 配置。这是配置名称，不是对模型权重或部署地点的独立认证。运行于临时隔离 profile，经发布安装器接入，不修改用户日常配置。

第一轮仅请求自建回环 /alpha 一次，记录 protected_access 后暂停；实际压缩；第二轮只复用原结果，生成 REPORT.md 和当前专项产物。该任务明确不需要额外扫描或联网研究。

本轮进行了三次受限运行。前两次未形成完整交付，保留失败记录，分别暴露了：不同文件被同一个 work 误去重；工具参数尚未通过校验就留下失败检查；旧 review 入口缺省有效期不一致；模型会传 JSON 编码的 request。对应修复后重跑同一场景，没有把前两次的正常进程退出算作成功。

## 范围与回退

没有重新对比 reverse；没有验证长时间、多目标复杂逆向或全部专项；没有更新 Kali 或证明 Pi/OpenCode 具备同等宿主钩子。向量服务仍为可选，默认自动召回使用已有本地词法检索。

适配器只能拦截已适配的结构化文件路径和协作工具归属，不是操作系统沙箱。语义质量仍需当前 Agent 根据实际证据复核，不能承诺不再跑偏。
