# 分类组合与节点复盘验证 · 2026-10-02

## 范围

本轮实现了组件分类/来源索引、现有方法与能力的组合入口、DSH 路由接入和证据关联节点复盘。没有执行上游仓库程序、扫描外部目标、部署新服务、修改用户日常 DSH profile 或安装全局 Skill。GitHub 调查是公开 API 元数据和固定版本源码/文档选读。

## 已观察结果

- 最终本地全量测试：158 项，155 通过、3 项按 Windows 平台条件跳过。设置 FUSION_DSH_RUNTIME 指向现有 DSH SDK，真实 SDK schema/调用/恢复场景参与运行。
- 组合覆盖现有每个专项/能力配对，输出限于一个专项和当前事件约定；错误配对拒绝，纯文字宿主明确不具备 hook。组合本身没有目标调用。
- DSH 真实工具路径先返回组合方法，再调用本地受控文件读取；回执保存方法与组件指纹，组件变更使旧路由重新准备。既有重复执行抑制和暂停边界仍通过。
- 原生 node-review 通过 DSH SDK 的真实 schema 和会话绑定写入账本；恢复读回下一试验，没有额外目标调用。伪造/未复核/其他案件回执拒绝，证据损坏后节点标 evidence_changed。
- 节点持久化在既有 events 表，重启可读；ready_to_deliver 不完成任务，有自报未决问题时拒绝该状态。节点超出当前恢复预算时返回事件指针，原文不删除。
- 新组合输出在测试覆盖的所有现有配对下不超过 5,000 字符；整体恢复继续遵守原预算。字符数不是 token 数，不是宿主总上下文上限。
- 主入口从 5,419 缩至 3,483 个 Unicode 字符（约 36%）；详细宿主参数移至按需参考，专项方法原文仍在原位置。
- Skill 格式验证通过；最终发布文件集的引用、组件实现路径、固定来源 SHA/URL 由 validate_pack 校验。
- Sentrux 初次提示复杂函数增加，拆分目录查询与节点恢复职责后 gate 无退化项。未配置 .sentrux/rules.toml，因此 check 的架构规则验收仍未完成，不能计为通过。

## 没有据此声称的能力

未重跑真实模型对照，不把 SDK 合同测试当作模型会主动复盘、正确理解方法或稳定完成深入任务的证明。没有验证新版本在 Kali、Pi/OpenCode 的宿主行为，也没有将上游自报性能当成本包性能。

程序验证证据归属、完整性和当前关联。节点结论仍由当前 Agent 判断；historical_supported 不自动证明当前目标仍满足旧条件。完整攻击路径图、动态试验收益排序、防守遥测与统一清理复测仍是明确缺口。

## 更新与回退

目标机更新 Skill 后，用包内 install_dsh_adapter.py 更新原 DSH profile 并重启，使四个 adapter 与技能包保持同版本。仅更新 Skill 不会改变已加载的宿主代码。

回退保留案件目录和原始证据，恢复上一版本技能包与四个 adapter 并重启。旧程序会忽略新的 node_reviewed 事件；数据库结构未变，不删除历史。调查文档和快照为只读参考，不是运行依赖服务。
