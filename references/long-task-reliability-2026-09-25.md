# 长任务恢复与执行内核验证（2026-09-25）

## 借鉴与落实

用户提供的架构截图只作为组织方式参考。截图中的技能数量、目录体积和“0 fail”没有可复核的测试依据。本轮借鉴执行内核、阶段产物和方法/工具/案件分层，保留现有三层路由，没有照搬大规模工具目录或膨胀入口规则。

[LangGraph 的持久化说明](https://docs.langchain.com/oss/python/langgraph/persistence)区分单会话检查点与跨会话存储；[Anthropic 的长任务实践](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)强调逐项推进、留下可恢复进度和实际验证。本包沿用已有 SQLite 案件、笔记与事件，不新增框架、依赖或数据库迁移。共享经验仍经单独审核，不能覆盖案件事实。

这次落实为代码的行为：

- 新 DSH 任务的目标检查必须给出稳定的 work.key 与条件；同目标、版本、身份、能力和条件下，换工具仍复用原检查。实际工具参数和回执独立保留。旧会话兼容原调用指纹，不猜配历史任务。
- 恢复时返回相关已复核结果、证据位置、适用身份/版本以及相关反证；直接/间接前置结果优先，其次目标检查，最后文件整理记录。已过期或证据改变的结果不标为可复用。
- 当前检查全 done 后仍恢复当前专项方法，避免把“刚才这次调用结束”当作“方法已经不需要”。next_action 区分复核、核对中断、执行和解除阻塞；依赖受阻不妨碍独立检查。
- 可选 next 在调用前保存为未执行计划；真正继续执行时清除旧 checkpoint，避免恢复后回到已走过的阶段。
- 已完整捕获但未完成 record 的宿主结果只补记原回执，不重发工具，不自动认定成功。没有可验证结果的未知调用保持待核对。
- CLI 默认最多 6,000 字符；DSH 连同宿主头与指引的整条恢复消息最多 8,000 字符。省略项可查询；必要约束超限明确报错。字符限制不是 token 或总会话账单限制。

## 自动化回归

执行 `python -X utf8 -m unittest discover -s tests`：143 项，140 通过，3 项受本地 Windows 环境条件限制跳过。其中 DSH 包装测试实际运行 14 个 Node 场景。

新增验证包括：

- 12 次会话对象重建和恢复消息移除后，同一问题换工具仍只产生一次真实回环 HTTP 请求；改变对照条件才执行第二次。该用例模拟压缩后的可见历史丢失，不冒充真实模型压缩。
- 注入“宿主结果已落盘，写账前进程退出”，重建会话两次恢复后仍只有一次实际执行，回执进入待复核状态。
- 无结果的中断不会被自动重发；跨会话不串案；执行后旧 checkpoint 不再回指旧步骤。
- 80 个未决调用分页恢复；长期历史中的前置结论、反证、过期/篡改证据和辅助记录优先级；整个恢复消息与 Unicode 字符预算。
- Windows CI 曾暴露长路径使历史路由明细超出预算；已改为按剩余预算装入历史决策，保留当前方法、适配器定位与完整事件指针。新增长明细回归，并在加长临时目录下重跑业务方法测试。

发布副本的技能格式、196 处本地链接、13 个专项、27 个方法分支与 22 项能力校验通过。结构 gate 无退化；仓库未配置 sentrux 自定义架构规则，不能声称该规则检查通过。

## 真实 DSH 模型续跑

环境：Windows、DSH 0.1.2-rc.1，使用已有配置的 bendi / Qwen3.8-27B-Uncensored 服务。名称来自配置，不代表已独立验证权重或在本机部署模型。采用临时隔离 profile，通过发布包内的安装器接入组件，没有修改日常 Agent 配置。

任务：第一轮只读取受控回环 `/alpha` 一次，记录 `protected_access` 后暂停；实际压缩上下文；第二轮只复用该结果，按当前专项生成报告及产物。任务没有要求扫描、联网研究或复杂逆向，不据此推断这些能力已经通过。

## 使用边界

这是限定任务的恢复与交付验证，不证明所有专项、复杂逆向或长时间多目标工作都已可靠；此前困难 JS 任务未通过的记录仍然有效。没有重新测试 reverse，也不据此宣称全面优于它。

work 条件仍需要准确描述，程序不能自动理解任意 shell 是否实质重复；能力标签也不能证明工具选择正确。方法卡持续可见和入口拦截能减少脱轨，但不能保证模型的每个推理步骤正确。报告引用真实回执、文件存在都不能代替语义核验。

升级需要同步更新 Skill 和当前 DSH profile 的宿主组件，见[安装与回退](host-adapter.md)。单独复制 Skill 文本不会启用宿主约束；本轮没有更新用户 Kali，也没有验证 Pi/OpenCode 的同等 hook 行为。
