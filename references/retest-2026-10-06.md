# DSH 待复核清单修复与续测记录

本次只修复已经复现的收尾问题：压缩恢复摘要省略了部分待复核回执，交付检查却依赖该摘要返回待办，导致 Agent 反复调用 `finish` 才逐条发现未复核项。没有调整漏洞方法、测试目标或工具权限。

## 修复

- 交付检查直接查询当前案件账本，独立于压缩摘要，最多返回 12 条回执的 ID、检查 ID 和状态。
- 新增 `query --kind attempts --status review --brief --limit 12`，不加载历史正文；原查询默认格式保持兼容。
- 超过一页时返回刷新命令。复核后记录会离开状态筛选，下一页从 offset 0 刷新，避免沿旧偏移漏项。
- 查询和复核不重发目标请求，不自动把观察标为完成；其他会话的回执不进入当前案件清单。

## 已完成的验证

先添加回归用例，旧实现出现“恢复摘要省略回执，交付错误没有返回全部可容纳回执”的失败；修复后同一用例通过。用例覆盖 7 条完整列出、14 条分页、处理首批 12 条后找回剩余 2 条、跨会话排除以及不重复调用工具。

本地完整回归共 186 项，183 项通过、3 项跳过，包含实际 DSH SDK 桥接验证。专项 Python 用例 11 项通过。跳过项不计为通过。

## 实际 DSH 续测

三轮使用同一个 `opencode-free/longcat-2.5-preview-free`，DSH 0.1.2-rc.1 和固定镜像的本地 Juice Shop 20.2.0。之前使用的 Space Bunny 不在当时返回的可用模型目录中，因此本表不与上一份记录混合比较。所有靶场请求由 DSH 经 MCP 发出；评测端部署环境、被动采集并离线读取证据。

A 任务分两段，中间请求原生上下文压缩；B 是同工作区的独立会话和另一容器目标。时间预算不含压缩耗时。

| 轮次 | 版本 | A / B 预算（秒） | 实际 HTTP A / B | 报告 A / B | 原生交付 A / B |
|---|---|---|---|---|---|
| 1 | 修复前 | 180+180 / 120 | 12 / 10 | 有 / 有 | 无 / 无 |
| 2 | 修复前，延长预算 | 240+240 / 180 | 10 / 6 | 无 / 无 | 无 / 无 |
| 3 | 本次修复 | 240+240 / 180 | 12 / 6 | 有 / 无 | partial / 无 |

第一轮 A 出现 5 次“尚有未复核工作”的交付拒绝。第三轮 A 出现 1 次同类拒绝，随后完成 14 条回执复核，保存报告、阶段报告并登记 `partial` 交付；专项产物缺口仍保留。第三轮 A 在完成该交付后以 `max-tokens` 结束，B 仍超时。样本不足以证明所有任务的收尾或模型遵循已解决，也不证明这一次改善全部由本次修改造成。

共保留 3 轮、6 个目标会话、56 次实际 HTTP、180 份哈希核验通过的登记产物。只有 1 个会话登记了原生部分交付，没有完整交付；报告存在、回执复核和漏洞结论正确性分别核对，未进行独立漏洞成绩评分。

## 保留的失败与限制

- 第二轮 A 的压缩调用返回连接错误，不能作为压缩恢复成功样本。第一、三轮有真实压缩完成事件。
- 第二轮 B 访问了该测试题明确排除的 `/api/Challenges` 评分接口，因此其能力成绩无效；该样本仍保留在记录中。测试题的路径排除目前只写在提示中，本次修复没有新增路径级执行约束。
- 第三轮 B 超时且未交付，长任务稳定完成仍有缺口。
- 实测恢复消息最大 7,995 字符；这不等于总上下文或总 token 低。提供商 usage 字段单独保留，不另加缓存字段估算费用，也不包含未返回的压缩用量。
- 这是小样本探索性测试，没有完成盲测、与 reverse-skill 的正式对照或 Kali 端验收。原始证据和模型认证配置保留在私有测试目录，公开文件不包含身份令牌和完整模型内部推理。

各轮源码快照哈希、时间、工具数、压缩事件和交付状态见 [脱敏指标](../benchmarks/retest-20261006.json)。此前的 [改进循环](reliability-cycle-2026-10-06.md) 保持原样。
