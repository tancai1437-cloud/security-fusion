# DSH 路由与执行验证 · 2026-09-26

本轮针对“加载后自由发挥、不走专项、不调用实际工具”改造 DSH 入口。以下区分程序约束和真实模型行为，不把 route_ready、退出码 0 或文件数量当作完成。

## 改动与可观察条件

| 断点 | 处理 | 验证依据 |
|---|---|---|
| 模型手填专项/能力后直接调用，方法在结果后才出现 | route 先返回专项原文生成的方法卡、当前可见工具 schema，再 execute | 未准备的调用没有工具回执；下一次带同会话 route_id 才执行 |
| 工具名存在却未说明能力对应关系 | 现有清单/宿主接口/显式配置匹配；多候选择一，缺失返回缺口，自定义工具需说明适用性 | 回执标记 manifest_name_match / host_interface / host_config / agent_explained_fallback；均不冒充健康探测 |
| 换工具、会话或方法后误用旧路由 | 路由绑定 owner、专项、能力、工具/schema、方法文件版本；最近六项按会话保存 | 跨会话/改工具拒绝；方法或 schema 更新重新准备；改变参数时显式给本次 work |
| 加载后直接结束，或用另一个执行入口绕过 | ready 状态也有限纠正；原生准备后禁止 CLI dispatch 绕过 | 最多两次纠正，随后记录未执行；分析请求可 suspend，不自动发目标请求 |
| 文件内容套两层 JSON 导致连续失败 | save 的顶层 file_path/content，仍调用真实 write 并捕获版本 | 特殊引号、换行、中文、JSON 内容按原字节写入本案 |
| 读规则、读账本也要人工复核，引起整理循环 | 成功读取本包/本案材料自动记读取完成；单点任务沿当前专项交付 | 任意目标材料和失败结果不自动判成功；保存/读取都不代表业务结论通过 |
| 带 route_id 的单独 review 误触发旧参数 | route_id + review 作为只复核处理 | 不新增工具调用；review / retest_reason 不保存在复用参数中 |
| 把写报告称作“分析”，用 suspend 解除全部拦截 | 暂停放行无关工作，旧目标/本案私有路径及已用 MCP 仍受控 | 结构化路径、命令中的明确路径、固定目标及旧 MCP 的无参数调用也覆盖；不是任意脚本沙箱 |

未替换主模型做自然语言理解。任务是否激活 Skill、语义上选择哪个专项、如何判断观察和结论，仍由 Agent 决定。程序保证调用接口和证据链可检查，不保证所有方法步骤均被正确理解。

## 真实模型联调

环境为 Windows、DSH 0.1.2-rc.1、独立临时 profile。使用现有配置项 `bendi / Qwen3.8-27B-Uncensored`，名称不等于独立鉴定模型权重。未更改日常 profile 或全局已安装 Skill。测试提示没有点名 security-fusion，也没有提供 route/execute 命令。

测试有明确时限：驱动约 420 秒、外层进程 480 秒，最多 32 次顶层工具调用；不是无限自动重试。实际执行器是连接到回环 HTTP/自建 JS 样本的 stdio MCP，未使用伪造成功响应。

### 中途失败样本，保留而不删除

1. Web 初版：Agent 自行加载 Skill，进入 fusion-web，实际 MCP 请求 1 次；完整回执与阶段文件均落盘。压缩遮蔽 13,426 tokens 后没有重复请求，但写报告连续发生嵌套 JSON 解析错误，未 finish。21 次顶层调用、2 次实际执行。判定：路由/调用通过，完整交付失败；据此增加单层 save。
2. JS 样本：自行进入 fusion-js，读取代码与输入、实际执行样本 1 次，并进行了本地推导。PowerShell 引号错误被明确复核为失败，再带理由重试；不是重复执行样本。保存了分析与专项文件，但 30 次顶层调用后仍未在时限内交付。判定：路由/实测通过，收尾效率失败。
3. 同一 JS 案件重启并真实压缩：压缩遮蔽 40,601 tokens，复用了旧样本结果，没有重新执行样本；但转去读取多个报告/验收规则并逐一记账，仍未 finish。保留原案和全部真实回执。此后削减默认收尾分流，成功的本案材料读取自动记完成。
4. 现有 `bai / glm-5.3-flash` 的最小工具调用连通探测超时，未将其当作替代模型的成功验证。
5. Web 后续版本再次自行路由并只请求目标 1 次，报告与专项文件实际写出，但模型把本案证据整理称作“只分析”，调用 suspend 后直接访问材料，又错误拼接过证据路径。顶层调用达到 33 次，未 finish。保留全部失败；据此修正暂停的资源边界，并兼容 action=review 的结构化 request.review，消除与旧 CLI 参数入口的混淆。

### 修正后的 Web 续跑：通过限定交付

保留同一 Web 案件继续，未重新建案、未重取目标证据。最终版本通过 3 次结构化 review 和 1 次 finish 完成交付：mode=finished、adherence=delivery_recorded、closure=submitted。账本 5 项 done，专项产物和目标验收缺口均为空；全部宿主捕获件/产物快照的哈希校验通过。

整个案件的真实叶子调用为 1 次 MCP HTTP 读取 + 4 次文件写入，最终续跑没有新增叶子调用。报告正确保留 protected_access=false，并说明仅观察一份基线、其他检查未测、执行器未返回响应头。不是完整 Web 安全评估。

首次压缩实际遮蔽 14,260 tokens；当前工作集最大 7,962 UTF-16 单元。后续额外强制压缩被 DSH 拒绝：`ManualCompactionError: manual compaction could not produce a smaller summary`，该失败未产生目标调用。保留原先已压缩的会话继续后才完成上述 4 次调用，不能把第二次强制压缩写成通过。

完整轨迹包含之前的 33 次顶层调用与失败，以及最后 4 次成功续跑，合计 37 次；不能将“4 次续跑”宣传为从零到交付的成本。JS 长任务收尾仍未在限定时限内通过，模型鲁棒性和整体效率仍有改进空间。

## 使用与回退

更新 Skill 后，还需用其 `install_dsh_adapter.py` 更新目标 DSH profile 的四个 adapter 文件并重启。只复制 Skill 文件无法更新宿主拦截。安装方法与边界见 [宿主适配](host-adapter.md)。没有给 Kali、Pi、OpenCode 的宿主行为作同等联调背书。

无新增依赖或数据库迁移；旧案件不删除。回退时将四个 adapter 作为一组恢复到此前版本，或用安装器 --uninstall 移除该 profile 的注册并重启，保留案件与证据。
