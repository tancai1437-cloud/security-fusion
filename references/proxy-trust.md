# XFF 与代理信任：从真实请求到服务端决策

观察到代理、client-IP 消费逻辑或相关配置后，提交 `http.entry` + `http.proxy-trust`。目标和 resource 是同一确切 URL、身份为 anonymous 时，`route/advance --execute-local` 可运行包内脚本，固定发出三次 GET：无 XFF、单个 TEST-NET 地址、两个 TEST-NET 地址组成的链。不附加凭据、不跟跳转、不枚举地址；其他身份/路径使用当前真实 HTTP MCP 工具保持上下文。

这三次请求检验外部字段如何被处理，不使用伪造内部 IP 作为默认尝试。GET 也必须适用于当前入口与既有任务范围。请求失败仍保存各次错误，退出非零；每次 socket 超时 5 秒，路由调用总体由 run 的 30 秒预算限制。

先选一条执行路径：当前 HTTP/MCP 逐组调用，或包内脚本一次跑三组。已有同目标、身份与条件的基线/对照时复用证据，只补未测组；不在 MCP 做完后再跑全组三次脚本作为收尾。需要跨工具复核时，先记录原证据缺少什么、具体变化条件和必须重测的组；用户要求的再次无头对照不等于要求再重发其他组。参数指纹只能识别相同调用，换工具或改写 shell 不会自动认出语义重复。

1. 比较实际 client-IP 字段、服务端日志/配置、响应状态和业务结果；保存原始请求头/响应头/响应体。脚本响应体最多保留 64 KiB，base64 编码并标注截断，hash 只覆盖保留部分。存在截断时补取所需部分，不能当作完整响应。
2. 确认客户端实际 TCP 对端、入口代理是否重写/追加 XFF、应用信任哪些代理或多少跳；多跳链按当前配置解释，不能默认取最左字段。直接访问源站只在该地址已经属于本案范围且确实可达时作为独立工作项；脚本不会自动跟到源站。
3. 若只是页面反射标记或诊断接口展示，记录“输入可影响显示”。若用于限流键、审计归属或权限控制，分别验证实际受影响决策；三者不能互相替代。动态页面、时间戳、缓存、负载均衡和统一错误页都可能造成响应差异。
4. 比较正确配置下的阴性对照。只有身份与其他条件保持一致、服务端保护决策确实受到不可信字段控制，并且证据排除了正常路由/缓存差异时，才交 candidate-review。三次都不变也不能证明所有代理路径安全。

脚本 `fusion_proxy_probe.py` 输出 observations_only，不自动报漏洞。继承的代理环境变量不会用于该适配器；需要既有 Burp/代理会话时走宿主 HTTP 工具。调用、复核和重跑均遵守已有案件账本；同一已复核检查不会再次发三次请求。

依据：[MDN X-Forwarded-For](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Forwarded-For)。方法为本包独立编写，不携带上游批量 bypass 字典或 payload 库。
